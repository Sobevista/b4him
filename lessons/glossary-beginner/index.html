The n8n Track · Glossary I

Eighteen Words, Each Said Four Ways.

What you'll be able to do: say any of these eighteen words four ways — the precise definition, the one a non-technical colleague would understand, the everyday thing it's like, and the mistake it causes — and notice, in your own speech, which words you can only say one way.

The invariant

A word you cannot say four ways — technical, plain, analogy, and the mistake it causes — is a word you have not learned. You have only heard it.

Why it matters: this is not about n8n. Every field hands you vocabulary that sounds like understanding, and the gap only shows up under load — the moment you have to explain it to someone who doesn't share your jargon, or the moment the thing breaks and you discover you knew the word but not the failure it causes. The four rows below are a test you can run on any word in any field: if you can only fill one row, you found a hole. This page is a tool glossary. The invariant under it isn't.

Why this page exists

I kept nodding along. Somebody would say idempotent or payload and I'd nod, because I sort of knew, and asking felt like admitting I'd been nodding for a while already. Then something would break and I'd find out that "sort of knew" and "knew" are not the same shelf.

So I started writing every word down four ways. The technical row, because that's the one the documentation speaks. The plain row, because if I can't say it to someone outside the room I don't have it yet. The analogy, because that's the one that actually sticks. And the common mistake, because most of these words cost me something before I understood them, and the cost is the part worth handing over.

The fourth row is the one I'd skip if I were you, so it's the one I gave its own shading. Read it before you think you need it.

Where the analogies end

Every analogy below is a ladder, and a ladder is for climbing off.

Where the analogy ends: the everyday comparisons here — the dishwasher, the conveyor belt, the doorbell — all describe machines you can see stop. You know when the dishwasher didn't run. Software's whole difficulty is that it fails quietly: a workflow can not-run for six days and look exactly like a workflow that ran perfectly. Every analogy on this page is missing that. Keep the picture; drop the reassurance that comes with it.

Append

Beginner

Technical
A write operation that adds a new row (or record) to a data store on every execution, regardless of whether an identical record already exists.
Plain
Every time the workflow runs, it adds a new entry — like a growing list of receipts.
Analogy
A hotel clerk who checks every guest into a new room without ever checking if they already have one. Efficient for truly new data. Dangerous for data that might repeat.
Common mistake
Using Append when the same event can fire more than once (for example, webhook retries). Leads to duplicate records. Fix: use Upsert with a unique identifier, or deduplicate upstream.

Automation

Beginner

Technical
A sequence of programmatic operations triggered by an event and executed without ongoing human input.
Plain
A set of instructions that run themselves when something happens, so you do not have to.
Analogy
A dishwasher. You load it (trigger), press start (activation), and it runs the full cycle (workflow) without you standing there washing each item by hand.
Common mistake
Confusing automation with elimination. Automation removes repetitive manual steps — it does not eliminate the need to design, monitor, and occasionally fix the process.

↑ back to the list

Branch

Beginner

Technical
A conditional routing operation where the execution path diverges based on the evaluation of one or more conditions against the current item's data.
Plain
A fork in the road. The workflow checks a rule, then goes left or right depending on what it finds.
Analogy
A post office sorting machine. Every package goes through the same scanner, but the scanner reads the ZIP code and flips the right switch — this package goes to the Chicago belt, this one to Miami.
Common mistake
Testing only one branch path and assuming the other works. Always test the TRUE path and the FALSE path (and every Switch output) before activating a workflow.

↑ back to the list

Canvas

Beginner

Technical
The visual workspace in n8n where nodes are placed and connected to form a workflow graph.
Plain
The whiteboard where you draw your automation by placing boxes (nodes) and connecting them with arrows.
Analogy
A whiteboard in a planning session — except this whiteboard executes itself. The arrows you draw become real data pipelines.
Common mistake
Using the canvas view as a substitute for reading the data panel. The canvas shows you the structure of your workflow. The data panel shows you what actually happened when it ran. You need both.

↑ back to the list

Condition

Beginner

Technical
A boolean expression evaluated at a Branch node that determines which execution path an item takes. Conditions compare values using operators (equals, greater than, contains, and so on).
Plain
A rule the workflow checks. If the rule is true, go this way. If not, go that way.
Analogy
An eligibility check on an application form. "Annual income must be greater than $50,000." The form either passes you through or rejects you based on whether your number meets the rule.
Common mistake
Writing a condition with a type mismatch — comparing a string "50" to a number 50 using a numeric operator. The condition never matches even when the value looks right. Always check the data type in the data panel before writing a condition.

↑ back to the list

Connection

Beginner

Technical
A directed edge in the workflow graph that carries item arrays from the output of one node to the input of the next. Connections carry output types: main, error, or custom.
Plain
The arrow between two nodes. It carries your data from one step to the next.
Analogy
A conveyor belt between two sorting stations in a warehouse. The belt carries packages (items) from one station's output tray to the next station's input tray.
Common mistake
Assuming a connection exists because nodes are visually close on the canvas. A connection is only real when you can see the arrow drawn between the nodes. Unconnected nodes do not share data.

↑ back to the list

Credential

Beginner

Technical
A stored authentication object in n8n (OAuth token, API key, username/password, service account file) that grants a node permission to access an external service.
Plain
A saved login that n8n uses to access your apps on your behalf — like a key you give it so it can open one specific door.
Analogy
A key card for a specific building. The key card is issued by the building (the external service), stored in your wallet (the Credentials list), and handed to the door reader (the node) each time you need access.
Common mistake
Embedding API keys directly in node configuration fields instead of using the Credentials system. Embedded keys cannot be rotated without touching every node that uses them. Always use a named credential.

↑ back to the list

Data Panel

Beginner

Technical
The inspection interface in n8n that displays the input and output item arrays for a selected node after an execution run.
Plain
The display that shows you exactly what each node received and what it produced when the workflow ran.
Analogy
The readout on a factory quality-control station. After each piece passes through, the readout shows what went in and what came out. If something looks wrong, you look at the readout, not at the machine.
Common mistake
Debugging workflows by reading the node configuration instead of the data panel. The configuration tells you what you intended. The data panel tells you what actually happened. Always read the data panel when something is wrong.

↑ back to the list

Execution

Beginner

Technical
A single run of a workflow from trigger firing to completion or failure. Each execution produces a timestamped record in the Execution Log with per-node input/output data.
Plain
One time your workflow ran — from start to finish, or to wherever it stopped.
Analogy
One batch in a cookie factory. The same recipe (workflow), the same equipment (nodes), but one distinct production run with its own record: start time, end time, what came out.
Common mistake
Using the terms "execution" and "workflow" interchangeably. A workflow is the blueprint. An execution is one run of that blueprint. A workflow runs many executions.

↑ back to the list

Expression

Beginner

Technical
A dynamic value written inside double curly braces {{ }} that is evaluated at runtime against the current item, node output, or environment variable.
Plain
A formula you write in a node field that gets filled in with real data when the workflow runs.
Analogy
A mail-merge field in a letter template. The template says "Dear {{ first_name }}," and the merge fills in the real name when the letter is printed. The expression is filled in when the workflow executes.
Common mistake
Writing an expression that references a field name incorrectly — wrong case, wrong nesting level, a typo. The expression evaluates to undefined silently: no error, just missing data. Always verify field names in the data panel before writing expressions.

↑ back to the list

Item

Beginner

Technical
The fundamental unit of data in n8n. A single JSON object processed by a node in one pass. Nodes receive arrays of items and produce arrays of items.
Plain
One piece of data. If your webhook receives one form submission, that is one item. If it receives a batch of 50, that is 50 items.
Analogy
One customer in a queue. The cashier (node) processes one customer at a time, but can process the entire queue (array of items) in sequence. Each customer carries their own basket (JSON object) of data.
Common mistake
Expecting one output item when the upstream node produced five. Item counts can change at any node. Check the item-count badge on each node after an execution to confirm how many items are flowing through.

↑ back to the list

JSON

Beginner

Technical
JavaScript Object Notation. A lightweight, human-readable data format using key-value pairs, arrays, nested objects, strings, numbers, booleans, and nulls. The native data format of n8n.
Plain
The format n8n uses to store and move data — a structured list of labelled values, written in curly braces.
Analogy
A standardized form. Every field has a label ("name") and a value ("Maria"). Nested sections — like "address": { "city": "Austin" } — are sub-forms attached to the main form. Arrays are tables with multiple rows on it.
Common mistake
Confusing JSON strings with JSON numbers. { "score": "87" } contains a string. { "score": 87 } contains a number. They look similar and behave differently in conditions and calculations. Always check the data type, not just the value.

↑ back to the list

Mapping

Beginner

Technical
The configuration of a node that specifies which input fields are read and how they are assigned to output fields, node parameters, or external service columns.
Plain
Telling a node which data goes where — like filling out a form by pulling answers from a previous document.
Analogy
A customs declaration form at the border. You have a passport (your data), and the form has specific fields. You map your passport information into the form fields in the right order.
Common mistake
Assuming field names are case-insensitive. Email and email are different field names in JSON. A mapping that references the wrong case will silently produce empty values.

↑ back to the list

Node

Beginner

Technical
A discrete processing unit in a workflow. Nodes receive item arrays, perform an operation (transform, request, decision, and so on), and produce item arrays. Each node type has a defined set of configurable parameters.
Plain
One step in your automation. Each box on the canvas is a node — it does one specific job.
Analogy
A workstation on an assembly line. Each station receives the work, does its specific task — drill, paint, inspect — and passes it to the next station. The product (data) is transformed at each station.
Common mistake
Adding a node to the canvas and assuming it runs. A node only runs if it is connected to the active execution path and the workflow is either in test mode or activated.

↑ back to the list

Payload

Beginner

Technical
The data body of an HTTP request received by a Webhook trigger node. Typically a JSON object containing the event data sent by the external system.
Plain
The data that arrives with a webhook request — the content of the message, not the envelope.
Analogy
The contents of a package, as distinct from the shipping label (the HTTP headers). The label tells you where it came from and how it was shipped. The payload is what is inside.
Common mistake
Confusing the HTTP headers with the payload body. Both are available, but most workflows operate on the payload body, not the headers. If your expected field is missing, check whether it arrived in the headers instead.

↑ back to the list

Schema

Beginner

Technical
The defined structure of a data object: its field names, data types, required versus optional status, and valid value ranges. In n8n, schemas are implicit — not enforced by default — unless validation logic is added.
Plain
The template that says what fields your data must have, what type each value should be, and which fields are required.
Analogy
A standardized form with labelled fields and type requirements. "Date of birth: MM/DD/YYYY (required)." Submit it in the wrong format and it should be rejected. Without schema enforcement, the wrong format gets through silently.
Common mistake
Assuming the tool enforces a schema automatically. It does not. If a field is missing or the wrong type, it will usually continue without error, and the bad data reaches your database. Schema enforcement must be added explicitly.

↑ back to the list

Trigger

Beginner

Technical
The first node in a workflow, defining the event or schedule that initiates execution. Without a trigger, a workflow does not run. Three types: push (Webhook), pull (Schedule), and manual.
Plain
The on-switch for your workflow. Something has to happen first — a trigger defines what that something is.
Analogy
A doorbell. Your workflow is inside the house. The doorbell wakes it up when someone rings. Without a doorbell, the workflow never knows anyone arrived.
Common mistake
Confusing the trigger with the workflow. The trigger is just the first node. If the trigger fires but a later node fails, the workflow errored — the trigger worked correctly. Check the execution log at the node level to find where the failure actually occurred.

↑ back to the list

Workflow

Beginner

Technical
A directed acyclic graph of connected nodes, beginning with a trigger and defining the full sequence of operations to be performed on incoming data.
Plain
The complete automation — all the steps connected together, from the trigger that starts it to the final node that ends it.
Analogy
A recipe. The trigger is "preheat the oven." Each node is a step: mix, pour into the pan, bake, plate. The workflow is the full recipe from start to finish. Running it once is making the dish once.
Common mistake
Editing a workflow while it is activated and receiving live traffic. Changes to an activated workflow can cause in-flight executions to use inconsistent node configurations. Deactivate, edit, test, then reactivate.

What isn't here yet

The source glossary carries twenty terms. Two of them — Idempotency and Run_ID — belong to the intermediate tier, and they're held for Glossary II, which isn't written yet. I'd rather you see the gap than not notice it.

They're the two that matter most the day something fires twice, so they're worth the wait. Append's mistake row above is the shadow they cast.

Validator Gates

  1. Gate 1: Without looking, say the difference between a workflow and an execution. One sentence each.
  2. Gate 2: Four of the mistake rows above send you to the same place when something goes wrong. Find all four, and say in one sentence what they have in common.
  3. Gate 3: Why does the Append entry point forward to a term that isn't on this page? What does that tell you about the order these words should be learned in?
  4. Gate 4 (own words): Pick a word from your own field — one you use weekly and have never defined out loud. Write its four rows. If the fourth row is blank, you have found something worth knowing, and that is the point of this page.

Glossary complete — and if the four-row habit is the only thing you take from it, you got the invariant and can drop the tool. Next: Glossary II, the intermediate and advanced terms. Not yet written; it's next in the queue.
